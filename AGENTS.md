# AGENTS.md — Uptime Monitor Lite

## Миссия

Этот репозиторий — учебный полигон для постепенного освоения полного жизненного цикла цифрового продукта и DevOps.

Цель первого проекта — НЕ построить сложный SaaS и НЕ максимизировать доход.
Цель — самостоятельно понять и пройти путь от простейшей рабочей версии до развёрнутого, наблюдаемого и восстанавливаемого приложения.

Главный принцип обучения:

> От незнания → к пониманию → к выполнению с подсказкой → к самостоятельному выполнению.

## RULE-001

> Сначала сделать самую маленькую рабочую версию продукта, пройти полный цикл и только потом усложнять.

Не добавлять архитектуру, сервисы, библиотеки или инфраструктуру «на будущее», если они не нужны текущему этапу.

## Как Codex должен работать

1. Работать только с текущим этапом из `ROADMAP.md`.
2. Перед изменениями коротко объяснить:
   - что делаем;
   - зачем;
   - как пользователь проверит результат.
3. Делать минимальное изменение, необходимое для выполнения текущей задачи.
4. После изменения:
   - запустить доступные проверки/тесты;
   - сообщить результат;
   - обновить `PROGRESS.md`;
   - при новой ошибке добавить её в `ERRORS.md`;
   - при новом устойчивом навыке обновить `SKILLS.md`.
5. Не считать этап завершённым только потому, что код сгенерирован.
   Пользователь должен суметь объяснить основную идею своими словами или повторить ключевое действие.
6. Если есть несколько способов решения — сначала предложить самый простой.
7. Не переходить к следующему большому этапу без проверки текущего.
8. Не скрывать ошибки. Ошибка — учебный материал.
9. Никогда не помещать пароли, токены, API-ключи и другие секреты в Git.
10. Не усложнять проект преждевременной монетизацией, Kubernetes, микросервисами и другой инфраструктурой, пока текущий учебный этап этого не требует.

## Формат разбора проблемы

Каждую значимую проблему разбирать так:

**Проблема → Причина → Действие → Проверка → Результат → Ошибка → Правило**

## Формат ответа Codex

По возможности использовать:

### Сейчас
Одно конкретное действие.

### Зачем
1–3 предложения.

### Сделано
Какие файлы/строки изменены.

### Проверка
Команда или действие пользователя.

### Что нужно понять
Одна ключевая идея.

### Следующий шаг
Только один следующий шаг.

## Учебные ограничения

Пользователь быстро учится, но знания лучше закрепляются повторением и практикой.

Поэтому:
- регулярно возвращаться к уже изученным командам;
- использовать короткие чек-листы;
- просить повторить важное действие без подсказки;
- не перегружать теорией;
- связывать DevOps-инструменты с реальной потребностью проекта.

## Определение готовности

Навык считается освоенным не когда пользователь видел его, а когда он:
1. понимает назначение;
2. выполнял действие;
3. исправлял хотя бы одну связанную ошибку или умеет диагностировать её;
4. может повторить ключевое действие с минимальной подсказкой.
