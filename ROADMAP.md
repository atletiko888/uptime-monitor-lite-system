# ROADMAP.md — Uptime Monitor Lite

## Принцип

Дорожная карта идёт от простого к реальному.

Каждый этап должен давать работающий, проверяемый результат.

Не перепрыгивать через этапы ради «более профессионального» стека.

---

# Фаза 0 — Система обучения — 5%

Цель: подготовить репозиторий и постоянную память проекта.

Результат:
- `AGENTS.md`
- `RULES.md`
- `ERRORS.md`
- `SKILLS.md`
- `PROGRESS.md`
- `ROADMAP.md`
- первый Git commit

---

# Фаза 1 — Самая маленькая работающая версия — 15%

Цель:

Ввести URL и вручную запустить проверку.

Минимальный результат:

```text
URL: https://example.com

[ CHECK ]

ONLINE
HTTP 200
```

Изучаем:
- структура приложения;
- HTTP;
- frontend/backend на минимальном уровне;
- запуск локально.

Не добавляем:
- аккаунты;
- платежи;
- красивые дашборды;
- фоновые очереди;
- сложную базу;
- микросервисы.

---

# Фаза 2 — Git как рабочий процесс — 20%

Цель: научиться безопасно изменять проект.

Изучаем:
- repository;
- status;
- add;
- commit;
- diff;
- log;
- `.gitignore`;
- простое восстановление после ошибки.

Результат:
каждое значимое изменение имеет понятную историю.

---

# Фаза 3 — История проверок / база данных — 30%

Цель:

Сохранять проверки сайта.

Пример:

```text
example.com
18:01 ONLINE 200
18:06 ONLINE 200
18:11 OFFLINE
```

Изучаем:
- данные;
- таблицы;
- простые запросы;
- persistence.

---

# Фаза 4 — Docker — 40%

Цель:

Запустить приложение в контейнере.

Изучаем:
- image;
- container;
- Dockerfile;
- ports;
- environment variables;
- volumes — только если понадобятся.

Критерий:
пользователь самостоятельно собирает и запускает контейнер.

---

# Фаза 5 — CI/CD — 50%

Цель:

Автоматически проверять приложение после изменений.

Сначала:
- lint/test/build.

Позже:
- автоматический deploy.

Изучаем:
- pipeline;
- job;
- step;
- secrets;
- failure.

---

# Фаза 6 — Реальный сервер — 60%

Цель:

Запустить Uptime Monitor Lite вне локального компьютера.

Изучаем:
- VPS;
- SSH;
- Linux server;
- processes;
- firewall;
- environment.

---

# Фаза 7 — DNS + HTTPS — 68%

Цель:

Открывать приложение по нормальному адресу через HTTPS.

Изучаем:
- DNS;
- domain;
- A/CNAME на базовом уровне;
- reverse proxy;
- TLS certificate.

---

# Фаза 8 — Безопасность — 75%

Цель:

Разобрать реальные поверхности атаки нашего приложения.

Минимум:
- секреты;
- input validation;
- SSRF как особенно важный риск для Uptime Monitor;
- зависимости;
- права доступа;
- firewall;
- обновления.

Важно:

Uptime Monitor принимает URL от пользователя, поэтому безопасность сетевых запросов — часть ядра проекта, а не дополнительная тема.

---

# Фаза 9 — Logging + Monitoring — 82%

Цель:

Понимать, что происходит с самим Uptime Monitor.

Изучаем:
- application logs;
- system logs;
- health checks;
- базовые метрики;
- alerts.

---

# Фаза 10 — Backup + Restore — 88%

Цель:

Не просто сделать backup, а реально восстановить систему.

Изучаем:
- что сохранять;
- где хранить;
- restore;
- проверку восстановления.

---

# Фаза 11 — Инцидент — 94%

Цель:

Намеренно сломать безопасную часть учебной системы и восстановить её.

Примеры:
- неправильная переменная окружения;
- упавший процесс;
- недоступная база;
- ошибка deploy.

Формат:

Проблема → диагностика → исправление → проверка → postmortem → новое правило.

---

# Фаза 12 — Финальный проход — 100%

Цель:

Повторить ключевой путь с меньшим количеством подсказок.

Финальная проверка:
- клонировать проект;
- настроить окружение;
- запустить локально;
- собрать Docker;
- внести изменение;
- провести его через Git;
- пройти CI;
- задеплоить;
- проверить HTTPS;
- найти логи;
- проверить мониторинг;
- восстановиться из backup;
- объяснить архитектуру своими словами.

После этого решаем:

1. улучшать Uptime Monitor;
2. сделать второй маленький проект быстрее;
3. переходить к коммерческому Micro-SaaS.

---

# Не сейчас

Пока намеренно НЕ добавляем:

- Kubernetes;
- микросервисы;
- Terraform;
- сложный cloud stack;
- регистрацию пользователей;
- подписки;
- платежи;
- мобильное приложение;
- AI-функции.

Они могут появиться позже, когда будет понятна реальная причина их использовать.
