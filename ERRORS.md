### ERROR-001 — CORS блокирует прямой fetch внешнего сайта

**Проблема**  
Frontend попытался выполнить `fetch("https://example.com")`, но браузер заблокировал запрос.

**Причина**  
Браузер применяет CORS-политику и не разрешает странице напрямую читать ответ от произвольного внешнего сайта без соответствующих разрешающих заголовков.

**Действие**  
Не пытаться строить Uptime Monitor только на frontend. Проверку доступности сайта нужно перенести в backend.

**Проверка**  
В DevTools → Console появилась ошибка CORS / Failed to fetch.

**Результат**  
Мы обнаружили архитектурную необходимость backend.

**Правило**  
Если браузер должен проверять произвольный внешний URL, сначала проверить ограничения CORS. Для uptime-проверок использовать backend.

### ERROR-002 — Подключён http вместо https

**Проблема**  
Backend должен был проверить `https://example.com`, но был подключён модуль `http`.

**Причина**  
В строке подключения было написано `require("http")` вместо `require("https")`.

**Действие**  
Исправили строку на `const https = require("https");`.

**Проверка**  
После перезапуска backend страница `http://localhost:3000` показала `STATUS: 200`.

**Результат**  
Backend успешно выполнил HTTPS-запрос к внешнему сайту.

**Правило**  
Если адрес начинается с `https://`, использовать модуль `https`. Если начинается с `http://`, использовать `http`.
